# Бриф: презентація воркшопу «Claude Code: від інтуїції до системи»

Цей файл — вхідна точка для Claude Code. Прочитай його повністю, потім
`docs/speaker-notes.md`, і тільки після цього починай будувати.

---

## Що будуємо

Одну самодостатню HTML-презентацію (`index.html`) для воркшопу на ~35 хвилин.
Відкривається у браузері на весь екран, працює офлайн, без збірки.

**Автор і спікер:** Наталі, фронтенд-розробниця, PettersonApps.
**Аудиторія:** розробники компанії, які вже щодня користуються Claude.
**Тон:** технічний, без менторства, без продажу. Вони знають основи.

## Вхідні матеріали в репо

- `docs/speaker-notes.md` — повний текст виступу по слайдах. **Це джерело правди
  для контенту.** Слайди — це опора для цього тексту, а не його переказ.
- `assets/*.svg` — готові діаграми. Вставляти інлайном у розмітку, не через `<img>`,
  щоб вони підхоплювали CSS-змінні теми.
- Референс попереднього деку тієї ж авторки: `figma-ai-slides.html` у репозиторії
  `NataliaMaheraPA/FigmaMCP-workshop`. **Візуальну мову беремо звідти.**

## Візуальна мова

Успадковуємо від попереднього деку — він уже фірмовий і подобається авторці.

- Темна тема. Зелений акцент PettersonApps.
- Manrope для тексту, Space Mono для коду, шляхів і технічних токенів.
- Плоскі поверхні, тонкі рамки, без градієнтів і тіней.

**Точні значення взяти з `figma-ai-slides.html`** і винести в `:root` як
CSS-змінні. Не вигадувати нову палітру.

### Що виправити порівняно з попереднім деком

1. **Переходи.** Там слайди перемикались через `display: none` → `flex`, тобто
   стрибком. `display` не анімується. Тримати всі слайди в DOM, керувати
   `opacity` + `transform: translateX()`, перемикати `pointer-events`.
2. **Скріншоти.** Стояли в бічній колонці й були нечитабельні з задніх рядів.
   Потрібен клік на зображення → лайтбокс на весь екран, Esc закриває.

## Технічні вимоги

- Один файл `index.html`. CSS і JS усередині. Без залежностей і без збірки.
- **Фрагменти:** елементи слайда з'являються поетапно по стрілці вправо.
  Атрибут `data-fragment` на елементі; стрілка спершу відкриває наступний
  фрагмент, і лише коли їх не лишилось — перемикає слайд. Назад — симетрично.
- **Навігація:** ← → стрілки, пробіл вперед, `Home` / `End`, клік по краях екрана.
- **Прогрес-бар** угорі, лічильник слайдів унизу праворуч.
- **Клавіша `B`** — затемнити екран повністю (коли треба, щоб дивились на спікера).
  Будь-яка клавіша повертає.
- **Клавіша `O`** — сітка всіх слайдів, клік переходить на слайд.
- **Deep links:** `#/7` відкриває сьомий слайд. Оновлювати hash при навігації,
  щоб можна було перезавантажити сторінку і не втратити місце.
- **Резервні слайди** (`data-backup`) не входять у лічильник і в основний потік:
  доступні лише через сітку або прямим hash. Це відповіді на очікувані питання.
- `prefers-reduced-motion` — вимикає переходи.
- Респонсив до ноутбучного екрана; друк у PDF як бонус, не пріоритет.

**Заборонено:** localStorage, sessionStorage, зовнішні CDN, аналітика.

## Правила подачі контенту

- **Слайд не дублює усний текст.** Максимум 5–7 рядків. Якщо на слайді абзац —
  це помилка, абзац належить у speaker notes.
- Код показувати як код: моноширинний, з підсвіткою, достатньо великим кеглем,
  щоб читалось із задніх рядів. Мінімум 18px.
- Шляхи до файлів (`~/.claude/settings.json`) — завжди моноширинним.
- Числа й результати — великим кеглем, підпис малим.
- Речення в один регістр, без Title Case і без КАПСУ.

## Порядок роботи

1. Прочитати `docs/speaker-notes.md` цілком.
2. Витягти токени дизайну з попереднього деку, зафіксувати в `:root`.
3. Зібрати кістяк: движок слайдів, навігація, фрагменти, лайтбокс. Перевірити
   на трьох порожніх слайдах, що все працює.
4. Наповнювати контентом послідовно, слайд за слайдом.
5. Наприкінці — прогнати всі слайди клавіатурою й перевірити, що жоден текст
   не вилазить за екран на 1366×768.

**Скріншоти** авторка додасть сама в `assets/screenshots/`. Передбач для них
місце в розмітці й підписи-плейсхолдери, які легко замінити.
